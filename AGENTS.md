# Чат (Slack) — учебный проект Hexlet

Упрощённый аналог Slack: каналы, сообщения в реальном времени, регистрация и вход.
Задание: https://ru.hexlet.io/projects/12/members/22522?step=N (шаг «Подготовка» и шаги 1–13). Требования шагов копятся в разделе «Шаги» ниже по мере прохождения.

## Целевой стек (требование проекта)

- Сборка — **Vite**. React с хуками, клиентский роутинг (react-router).
- **Серверное состояние** (каналы, сообщения) — **TanStack Query**: данные не хранятся, а кешируются; загрузка, обновление, индикатор загрузки, обработка ошибок.
- **Клиентское состояние UI** (открытый канал, показанная модалка, текущий пользователь) — **Zustand**: хранилище на хуках, без редьюсеров и экшенов.
- Эти два вида состояния держать раздельно: серверные данные — в Query, UI — в Zustand.
- Формы — **@mantine/form**.
- UI — **Mantine**. Внешний вид задаётся пропсами компонентов и темой; доступность (фокус в модалке, Escape, клавиатура в меню) берётся из компонентов Mantine.
- Свой CSS в проекте не пишется.
- Бэкенд — готовый `@hexlet/chat-server`: REST API и веб-сокеты (socket.io).
- Продакшен: сборка, деплой на Render, мониторинг ошибок (например, Bugsink).
- Эталонная заготовка Hexlet: https://github.com/hexlet-components/js-react-hexlet-chat — сверяться с ней по раскладке и конфигам.

## Интерфейс по демо Hexlet

Демо (скриншоты): https://files.hexlet.app/a/ose685. Тексты интерфейса брать отсюда дословно — по ним ищут элементы проверки.

- **Шапка:** «Hexlet Chat» слева (ссылка на `/`), кнопка «Выйти» справа — только для вошедшего.
- **Вход `/login`:** карточка с картинкой слева; заголовок «Войти», поля «Ваш ник» и «Пароль» (с глазом), кнопка «Войти»; внизу «Нет аккаунта? Регистрация». Клиентской валидации нет; ошибка сервера под паролем — «Неверные имя пользователя или пароль».
- **Регистрация `/signup`:** «Регистрация»; поля «Имя пользователя», «Пароль», «Подтвердите пароль»; кнопка «Зарегистрироваться». Ошибки: «От 3 до 20 символов», «Не менее 6 символов», «Пароли должны совпадать».
- **404:** «Страница не найдена», «Но вы можете перейти на главную страницу» (ссылка на `/`).
- **Чат `/`:** слева «Каналы» и кнопка «+», список `# general`, `# random`; у добавленных каналов — выпадающее меню «Удалить» / «Переименовать». Справа заголовок `# канал`, счётчик «N сообщений», сообщения в виде «**user**: текст», поле «Введите сообщение...» с кнопкой отправки.
- **Модалки:** «Добавить канал» / «Переименовать канал» — поле «Имя канала», кнопки «Отменить» / «Отправить»; «Удалить канал» — «Уверены?», кнопки «Отменить» / «Удалить» (красная).
- **Уведомления** внизу справа, например «Канал создан».

## Решения проекта

- **TypeScript** (свежий, сейчас 7.x), `strict`. Весь код — `.ts`/`.tsx`. Импорты с явным расширением (`./init.tsx`).
- Контракт проверки Хекслета требует `src/init.jsx`: он остаётся реэкспортом из `src/init.tsx`. Тест `__tests__/smoke.test.tsx` импортирует именно `src/init.jsx`.
- Линт и формат — oxlint + oxfmt с конфигами из эталонной заготовки (канон Хекслета). `make lint` = typecheck + oxlint + oxfmt.
- Версии зависимостей — последние на момент установки.
- Тесты — Vitest + Testing Library в `__tests__/`, окружение jsdom, общий setup — `__tests__/setup.ts` (заглушки `matchMedia` и `ResizeObserver` для Mantine, `Element.scrollTo`, сброс сторов, `fetch` — через `vi.stubGlobal`). Сокет в тестах — заглушка с `on`/`emit`, приложение рендерится через `init` (см. `__tests__/messages.test.tsx`). Компонент вне `App` рендерить внутри `MantineProvider`. Роутинг проверяется через `window.history.pushState` перед `render(<App />)`.
- `package.json` минимальный: только `name`, `private`, `type` и зависимости, без `scripts`. Все команды — в `Makefile` через `npx`.

## Шаги

Каждый шаг добавляет вводные и усиливает требования; более поздний шаг уточняет более ранний.

- **Подготовка (step=0).** Знакомство с проектом: цель и стек описаны выше. Результат — рабочее окружение готово.
- **Запуск проекта (step=2).**
  - Фронтенд в корне репозитория, бандл — в `dist`. Имя пакета — `@hexlet/code`.
  - `src/init` по умолчанию экспортирует async-функцию: принимает сокет, возвращает разметку, готовую к рендеру. Сокет — параметр (проверки подставляют свой), поэтому провайдеры, роутер и стили живут внутри `init`/`App`, а не в `index`.
  - `src/index` открывает сокет (`io()`), вызывает `init`, монтирует результат в `#chat`.
  - Dev-сервер Vite проксирует `/api` и `/socket.io` на `localhost:5001`.
  - `make build` — сборка; `make start` — `npx start-server -s ./dist` (отдаёт статику и API на 5001).
  - Деплой на Render (бесплатный тариф), ссылка на приложение — в README.
- **Роутинг (step=3).**
  - Маршруты `/` и `/login`; любой другой путь — страница 404.
  - На `/login` — форма входа (имя пользователя, пароль, кнопка отправки) на `useForm` из `@mantine/form`. Отправку на этом шаге не реализовывать.
- **Авторизация (step=4).**
  - JWT: форма шлёт `POST /api/v1/login` (`{ username, password }`), сервер отвечает `{ token, username }`.
  - Данные авторизации — в отдельном Zustand-хранилище `src/stores/auth.ts` с `persist` (ключ `auth` в localStorage), токен переживает перезагрузку.
  - После входа — редирект на `/`. Ошибка 401 показывается в форме: «Неверные имя пользователя или пароль».
  - Без токена `/` редиректит на `/login`; с токеном `/login` редиректит на `/`. Кнопка «Выйти» в шапке очищает хранилище.
  - Тестовый пользователь сервера: `admin` / `admin`.
- **Инициализация (step=5).**
  - На открытии чата грузятся `GET /api/v1/channels` и `GET /api/v1/messages`, токен — в заголовке `Authorization: Bearer <token>`.
  - Запросы и хуки данных — `src/api.ts` (`useChannels`, `useMessages` на TanStack Query). Ответ 401 разлогинивает.
  - UI-состояние — `src/stores/ui.ts` (Zustand). Текущий канал (термин — в `GLOSSARY.md`) отдаёт только `useCurrentChannel()`: выбранный, иначе первый. Кэш-хелперы в `src/api.ts` UI-стор не трогают и его не импортируют.
  - Данные запросов не устаревают сами (`staleTime: Infinity`): свежесть держат события сокета и перечитывание по `reconnect`.
  - Один `QueryClient` в `App`, кеш чистится при выходе.
  - Разметка как в демо: слева каналы, справа заголовок канала со счётчиком сообщений, лента и поле ввода.
- **Работа с чатом (step=6).**
  - Отправка — `POST /api/v1/messages` (`{ body, channelId, username }`) через `useSendMessage`; получение — событие сокета `newMessage`.
  - Подписки на сокет живут в `init.tsx` вне React и пишут прямо в кеш TanStack Query; поэтому `QueryClient` создаёт `init` и передаёт в `App`.
  - Сообщение приходит дважды (ответ POST и сокет) — `addMessage` отбрасывает дубль по `id`.
  - Медленная или пропавшая сеть: пока запрос висит, кнопка заблокирована; при ошибке — уведомление «Ошибка соединения», текст остаётся в поле. После `reconnect` сокета все запросы перечитываются.
  - Лента прокручивается к последнему сообщению; поле ввода в фокусе при смене канала и после отправки.
  - Сокет-события сервера: `newMessage`, `newChannel`, `renameChannel`, `removeChannel` (+ `renameMessage`, `removeMessage`).
- **Работа с каналами (step=7).**
  - Добавление, переименование, удаление — мутации `useAddChannel`/`useRenameChannel`/`useRemoveChannel` (`POST`/`PATCH`/`DELETE /api/v1/channels[/:id]`). Кеш правят функции `addChannel`/`renameChannel`/`removeChannel` — их же зовут обработчики сокета `newChannel`/`renameChannel`/`removeChannel` в `init.tsx`.
  - Имя канала: `useForm` + встроенный `hasLength({ min: 3, max: 20 })` («От 3 до 20 символов») и уникальность («Должно быть уникальным»), пробелы по краям обрезаются.
  - Создатель канала переходит в него (`AddChannel` в `ChannelModals.tsx`). Удаление уносит сообщения канала; кто был в нём — попадает в канал по умолчанию через правило `useCurrentChannel`.
  - Меню «Удалить» / «Переименовать» (кнопка `aria-label="Управление каналом"`) — только у `removable` каналов. Удаление — с подтверждением «Уверены?».
  - Модалки — одна `Modal` в `ChannelModals.tsx`, какая открыта — в Zustand (`modal` в `src/stores/ui.ts`). Формы — обычный `<form>`, Enter отправляет. Поле имени в фокусе (`data-autofocus`), при переименовании старое имя выделено.
  - Кнопки блокируются на время запроса; сетевые ошибки — уведомление «Ошибка соединения», модалка остаётся открытой. Успех — «Канал создан» / «Канал переименован» / «Канал удалён».
  - Вёрстка не ломается: длинные имена каналов обрезаются многоточием (`miw={0}` у flex-детей), длинные сообщения переносятся (`overflowWrap: anywhere`), списки прокручиваются.
- **Регистрация (step=8).**
  - `/signup`: «Имя пользователя», «Пароль», «Подтвердите пароль», кнопка «Зарегистрироваться». Все поля обязательны («Обязательное поле»), имя 3–20 символов, пароль от 6 («Не менее 6 символов»), подтверждение совпадает («Пароли должны совпадать»); проверка на blur и при отправке.
  - `POST /api/v1/signup` → 201 `{ token, username }`; 409 — «Такой пользователь уже существует» под именем. После успеха — вход и редирект на `/`.
  - Вход и регистрация шлют запрос через общий `authenticate` из `src/api.ts`; разметку карточки делит `AuthCard`.
  - Вошедшего пользователя `/signup` отправляет на `/`. Шапка с «Hexlet Chat» и «Выйти» (только для вошедших) — на всех страницах.
- **Интернационализация (step=9).**
  - Все тексты интерфейса — в `src/locales/ru/translation.json` (раскладка эталона Hexlet), в компонентах только `t("ключ")` из `useTranslation()`. Новый ключ: пишется `t("…")` в коде, затем `make i18n-extract` добавляет его в словарь (ключи там отсортированы) — текст вписывается под ключом.
  - `i18next-cli` (конфиг `i18next.config.ts`): `make test` сначала гоняет `make i18n-check` = `i18next-cli lint` (захардкоженные строки в JSX) + `i18next-cli status` (ключи из кода, которых нет в словаре).
  - Ключи в `t()` — только литералы: шаблонные строки извлекатель не видит. Извлекатель читает и комментарии — не писать в них `t("…")`.
  - Экземпляр i18next — `src/i18n.ts`: язык фиксирован `ru`, без автоопределения (требование автотестов). Ресурсы встроены, `initAsync: false` — переводы готовы синхронно, `App` оборачивается в `I18nextProvider`.
  - Ключи типизированы через `CustomTypeOptions`: опечатка в ключе — ошибка `tsc`.
  - Множественное число — суффиксы i18next: `messages.count_one/_few/_many/_other` + `t("messages.count", { count })`.
- **Всплывающие уведомления (step=10).**
  - Библиотека — `@mantine/notifications` (`<Notifications>` в `App`, `notifications.show` в коде). Тексты — через i18n (вне React — `i18n.t`).
  - Ошибка загрузки данных — общий `QueryCache.onError` в `createQueryClient()` (`src/api.ts`), уведомление «Ошибка загрузки данных» с `id`, чтобы не множилось. Запросы повторяются один раз (`retry: 1`).
  - Нет сети: `disconnect` сокета (кроме `io client disconnect`) — постоянное уведомление «Нет соединения с сервером» (`id: "offline"`), `connect` его убирает.
  - Неудачная мутация (отправка сообщения, каналы) — «Ошибка соединения» из общего `MutationCache.onError` в `createQueryClient`. Успех каналов — «Канал создан» / «Канал переименован» / «Канал удалён» в `onSuccess` самих мутаций в `src/api.ts`. Компоненты уведомления не показывают: только закрывают модалку / чистят поле, исключение `mutateAsync` гасят пустым `catch`. Вход и регистрация пока вне этого (не мутации).
- **Фильтрация нецензурных слов (step=11).**
  - `leo-profanity` через `censor()` из `src/profanity.ts`: встроенный английский словарь + русский (`add(getDictionary("ru"))`, не `loadDictionary` — тот заменяет словарь). Слово заменяется звёздочками той же длины.
  - Фильтруется до отправки на сервер: текст сообщения (`MessageForm`) и имя канала при создании и переименовании (`ChannelModals`). Уникальность имени канала проверяется по уже отфильтрованному имени.
- **Эксплуатация (step=12).**
  - Коллектор ошибок — Bugsink через `@sentry/react` (Bugsink принимает события Sentry SDK; трейсинг не включать).
  - `Sentry.init` — в `src/index.tsx`, не в `init`: проверки Хекслета зовут `init` напрямую. Ошибки рендера React — через `reactErrorHandler()` в опциях `createRoot`.
  - DSN — из окружения на этапе сборки: `VITE_SENTRY_DSN` (переменная сервиса на Render). Нет переменной — коллектор выключен; DSN в репозиторий не коммитится.
  - На Render переменная лежит в группе переменных (Environment Group), привязанной к сервису. Render CLI переменные и группы не меняет — только в панели; смена переменной требует пересборки (`render deploys create <srv> --wait`). Проверка: DSN виден в живом бандле, тестовая ошибка уходит `POST …/api/1/envelope/` с ответом 200.
- Сервер стартует с пустой лентой сообщений; seed-каналы — `general` и `random`. Данные в памяти — перезапуск всё сбрасывает.
